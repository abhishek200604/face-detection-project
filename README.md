## 🚀 Project Overview
This serverless web application allows users to upload an image and automatically detect the number of human faces within it. It leverages deep learning for face detection, text-to-speech for audible results, and automated notifications for alerting.

## 🎯 Objectives
- Build a fully automated, scalable serverless architecture
- Process image data using managed AWS AI services
- Provide both visual and audible feedback to the user
- Implement a secure, keyless CI/CD pipeline using GitHub Actions

## ✨ Key Features
- **Drag-and-Drop Web UI**: Clean, responsive frontend for uploading images
- **Face Detection AI**: Accurate identification using Amazon Rekognition
- **Text-to-Speech**: Audible results generated by Amazon Polly
- **Email Notifications**: Real-time alerts via Amazon SNS
- **Automated Deployments**: CI/CD driven by GitHub Actions and OIDC

## 🔄 End-to-End Working Flow
1. **Frontend Request**: User uploads a JPG/PNG image.
2. **Data Transfer**: Frontend sends the image as a Base64-encoded JSON payload to API Gateway.
3. **Trigger**: API Gateway synchronously invokes the AWS Lambda function.
4. **Storage**: Lambda decodes the payload and stores the binary image in S3.
5. **Analysis**: Amazon Rekognition detects faces and returns the count.
6. **Voice Synthesis**: Amazon Polly converts the result ("X faces detected") into MP3 speech and saves it to S3.
7. **Audio Access**: Lambda generates a pre-signed S3 URL for the MP3.
8. **Notification**: Amazon SNS publishes the detection result to the configured topic, sending an email to the confirmed subscriber.
9. **Display**: The website receives the JSON response, displaying the face count and providing an embedded audio player.

## 🧠 Face Detection Process
- Amazon Rekognition's `detect_faces` API is invoked by Lambda
- Identifies humans without requiring custom ML models
- Returns a list of detected face details
- Lambda simply counts the length of this list to determine the total faces

## 🔊 Amazon Polly Audio Generation
- Converts text (e.g., "7 faces detected in the image.") into lifelike speech
- Uses the `Joanna` voice
- Outputs standard MP3 format
- MP3 is stored in S3 and accessed securely via a time-limited pre-signed URL

## 📧 SNS Email Notification
- Alerts are sent automatically upon successful detection
- Uses a standard SNS Topic: `FaceDetectionNotifications`
- Only sends to the already-confirmed SNS email subscription
- Includes face count, generated statement, and S3 asset keys

## 🪣 S3 Storage Structure
- **Bucket**: `face-count-detection-project`
- **Images**: Stored under the `images/` prefix (e.g., `images/<uuid>.jpg`)
- **Audio**: Stored under the `audio/` prefix (e.g., `audio/<uuid>.mp3`)

## 🛠️ Troubleshooting

<details>
<summary><b>API Gateway CORS problems</b></summary>

- ❌ **Symptom**: Browser Console shows CORS blocked error.
- 🔍 **Cause**: Lambda failed to execute or API Gateway missing `Access-Control-Allow-Origin` header on 500 responses.
- ✅ **Fix**: Ensure Lambda handles exceptions and manually returns CORS headers in the 500 error block.
</details>

<details>
<summary><b>Lambda permission problems</b></summary>

- ❌ **Symptom**: CloudWatch shows AccessDenied exceptions.
- 🔍 **Cause**: `FaceDetectionLambdaRole` lacks necessary policies.
- ✅ **Fix**: Attach required policies (e.g., `AmazonS3FullAccess`) to the execution role.
</details>

<details>
<summary><b>S3 access problems</b></summary>

- ❌ **Symptom**: Error writing to S3 bucket.
- 🔍 **Cause**: Incorrect bucket name in environment/code or missing `s3:PutObject` permissions.
- ✅ **Fix**: Verify bucket name `face-count-detection-project` and ensure Lambda has write access.
</details>

<details>
<summary><b>Rekognition errors</b></summary>

- ❌ **Symptom**: `ValidationException` from Rekognition.
- 🔍 **Cause**: The S3 object does not exist yet when Rekognition is called, or bucket names do not match.
- ✅ **Fix**: Await/ensure the S3 `put_object` call completes before invoking `detect_faces`.
</details>

<details>
<summary><b>Polly errors</b></summary>

- ❌ **Symptom**: Speech synthesis fails.
- 🔍 **Cause**: Unsupported voice ID or missing IAM permissions for `polly:SynthesizeSpeech`.
- ✅ **Fix**: Use a standard voice like `Joanna` and attach Polly access policies.
</details>

<details>
<summary><b>SNS publish permission errors</b></summary>

- ❌ **Symptom**: Lambda throws an error when calling `sns.publish()`.
- 🔍 **Cause**: Lambda role missing `sns:Publish` access to the specific Topic ARN.
- ✅ **Fix**: Add SNS publish permissions to `FaceDetectionLambdaRole` targeting `arn:aws:sns:ap-south-1:358625410414:FaceDetectionNotifications`.
</details>

<details>
<summary><b>SNS subscription confirmation</b></summary>

- ❌ **Symptom**: No email received despite successful execution.
- 🔍 **Cause**: The email address was subscribed but never clicked the AWS confirmation link.
- ✅ **Fix**: Check your inbox for the AWS confirmation email and click "Confirm Subscription".
</details>

<details>
<summary><b>GitHub Actions OIDC AssumeRoleWithWebIdentity errors</b></summary>

- ❌ **Symptom**: CI/CD fails at the `Configure AWS credentials` step.
- 🔍 **Cause**: The IAM Trust Policy has the wrong GitHub subject (`repo:owner/repo:ref`).
- ✅ **Fix**: Ensure the OIDC trust relationship correctly matches the GitHub Repository ID and workflow context.
</details>

<details>
<summary><b>Lambda deployment errors</b></summary>

- ❌ **Symptom**: AWS CLI `update-function-code` fails.
- 🔍 **Cause**: Incorrect function name or ZIP file path in the GitHub Actions runner.
- ✅ **Fix**: Verify `--function-name FaceDetectionFunction` exactly matches the AWS console.
</details>

<details>
<summary><b>GitHub Actions Node 20 deprecation warning</b></summary>

- ❌ **Symptom**: Warning about Node.js 20 deprecation in workflow logs.
- 🔍 **Cause**: Standard GitHub Actions deprecation lifecycle for older runner action versions.
- ✅ **Fix**: This is a non-critical warning. Update action versions (e.g., `actions/checkout@v4`) when major releases drop.
</details>
